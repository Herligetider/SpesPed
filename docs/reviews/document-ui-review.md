## Actionable findings

1. **[P1] Manual revision payload fails the native schema.** `web/src/features/documents/DocumentWorkspace.tsx:237` constructs `DocumentRevise.document` without `request_key`. Native `backend/spesped/contexts/documents/schemas.py` requires that field because nested `document` is a `DocumentCreate`, which inherits `Command`. `send()` adds a key only to the outer object. Consequently every manual revision receives 422 and cannot save. Exact pinned schema validation reproduced `loc=('document','request_key'), type='missing'`. Supply a valid nested command coordinate in the UI payload, retaining the outer retry key semantics, and verify through the native endpoint.

2. **[P1] The selected revision editor uses unrelated new-document state.** `DocumentWorkspace.tsx:119` automatically selects the first document but does not initialize its editor; `DocumentPanel` at line 313 receives the same `draft` used by the new-document form. Only a manual list-button click invokes `loadIntoEditor`. A direct save therefore submits null subject/text and default sections instead of the displayed saved revision; after finding 1 is fixed this can overwrite existing prose. Editing the new-document form also changes the selected document editor. The review probe reproduced a displayed saved summary followed by a manual revision payload whose first section text was null. Furthermore `loadIntoEditor` at line 245 does not load configuration language/length, and `revise` resets topics to `[]`, so even clicking a Nynorsk detailed document before saving can silently change it to Bokmål/standard and remove topics. Keep creation and selected revision editing state separate, hydrate it with the selected exact revision/configuration, and preserve untouched fields.

3. **[P1] A denied refresh restores previously authorized pupil content.** `DocumentWorkspace.tsx:120` records a load error without clearing workspace, editor, proposal or saved recovery state. Once finally sets loading=false, the existing workspace is rendered again under the access-denied alert. With access withdrawn after a successful load, the probe confirmed `Saved sensitive prose` remains visible after the next workspace request returns 403. Clear protected state on denied/not-found reads and prevent late requests from repopulating it; verify both document prose and retained proposal/editor content disappear.

4. **[P2] Changing the interval leaves hidden old selections in the submitted basis.** Date handlers at `DocumentWorkspace.tsx:290` and line 291 update only date strings. The picker effect replaces option inventories at line 163, but never invalidates selected references, background references, goals, actuals, future plans, obligations, recipients, owners or section citations. A probe selected an October observation, changed the interval to December, observed the October checkbox disappear, then confirmed that create still submitted its reference. The native service rejects an interval source outside the period, leaving an invisible selection that cannot be unchecked; stale guardian or obligation choices have the same shape of problem. Invalidate dependent selections when the period/template/kind/recipient context changes and reconcile them against successfully refreshed authorized choices, including failed-choice reads.

5. **[P2] Evidence gaps cannot be explicitly handled through this UI.** `DocumentWorkspace.tsx:228` and line 235 always emit `handled_gaps: {}` and replace every section's `missing_inputs` with `[]`. The panel only displays snapshot gaps at line 339. Native `service.ready()` requires explicit handling of every snapshot/section gap before approval, including a valid guardian draft with no confirmed observations in the selected interval. There is no input or command path to provide those explanations; editing a document that already has handled gaps also discards them. Add per-gap human explanations, preserve existing missing-input/handled-gap data, and prove a legitimate missing-evidence draft can be revised and approved without inventing evidence.

6. **[P2] Contribution requests are not bound to the currently selected inbox document.** `DocumentWorkspace.tsx:364` accepts any fulfilled contribution-workspace request while the component is mounted. Open A, then B, resolve B first and A last: `selected` remains B while workspace/text/citations come from A. Submit at line 370 then targets document B with A's revision/version/source keys; the native exact-revision check rejects it, and the user edits the wrong assigned content. A successful submission can also call `open(selected)` after the user has switched elsewhere. Use a per-selection request generation/document identity guard and cancel stale completions, including post-submit reloads. This finding is based on the deterministic state transitions in code; the reviewer did not execute a contribution race probe.

7. **[P2] Changed source bases have no in-place recovery path.** The source-change effect at `DocumentWorkspace.tsx:190` clears the editor. `loadIntoEditor` at line 243 refuses it, and `DocumentPanel` at line 345 disables revision saving whenever source status is not current. Although the panel says old text is withheld until sources are reviewed, it offers no way to review/rebuild the existing document basis or create a new revision for late/recalled sources. Such a document remains permanently blocked in this workspace even when current authorized sources can be selected. Provide an explicit rebuild/review path that uses current source choices, records a new snapshot/revision, keeps unavailable old text withheld, and enables exact revision review only after that rebuild.

### Residual findings

8. **[P1] Late template inventory completion destroys unsaved text and gap explanations.** `web/src/features/documents/DocumentWorkspace.tsx:216` sets a new `editorTemplateSections` array after the selected document's template choices load, even when there is no template and the result is `[]`. The full editor hydration effect at line 270 depends on that array, so a normal network completion replaces the entire editor after the user has begun editing. The deferred-response reviewer probe displays the saved summary, types `Unsaved review edit`, then resolves template choices with an empty successful page; the editor reverts to the saved summary. The same hydration resets handledGaps and reason. Root independently observed a native 201 save returning handled_gaps:{} after filling the gap explanation and section text, and is capturing the outgoing command in `var/document-guardian-repair/evidence.json`. Hydrate document content/configuration on a selected exact revision change; apply template metadata without overwriting dirty text, reason or gap explanations. Verify deferred template success and failure while the user edits both ordinary and guardian documents.

9. **[P1] Rebuild mode leaks across selected documents and bypasses source-text withholding.** `DocumentWorkspace.tsx:384` sets global `rebuilding=true`; changing `selected` never clears it. The hydration effect then loads the next document's content regardless of sourceBad, and line 411 renders the editor whenever rebuilding is true. A deterministic reviewer probe starts rebuilding source-stale A, then selects source-stale B (a native-valid review_required response containing the old content). B's prior prose appears in its textarea while the panel says old text is withheld until source review. This is a source-review presentation failure, not evidence that the backend returns withdrawn content on forbidden access. Scope rebuilding to one exact document/revision, reset it on selection/source transitions, and ensure stale prose is never hydrated into the replacement editor.

10. **[P2, finding 7] A fully recalled interval cannot be rebuilt as an honest gap-only draft.** The rebuild save button at `DocumentWorkspace.tsx:415` requires `draft.sources.length>0`. When every interval source has been recalled or is unavailable, the UI can start rebuilding and accept independent text but can never save. The reviewer empty-inventory probe confirms the button stays disabled. Native document creation/revision explicitly supports absent evidence with `no_confirmed_observations_in_selected_period` and human gap handling; it does not require a positive observation. Permit rebuilding an honest empty basis and exposing/handling the resulting gaps, without requiring a substitute factual source.

11. **[P2, finding 7] Rebuild retains unavailable typed source dependencies.** The rebuild-start handler at `DocumentWorkspace.tsx:384` clears only sources/background and section citations; it retains old goals, actuals and futurePlans from the unavailable revision configuration. `revise()` at line 315 replays those identifiers. The reviewer probe supplies an unavailable old delivery ID, selects a new authorized interval observation, and confirms the outgoing revision still contains that delivery ID. Native collect resolves those typed references through their owners, so a recalled/withdrawn delivery, goal or future plan continues to fail even after the apparent replacement. Provide current typed choices during rebuild, or explicitly clear and require fresh selections; preserve the distinct meaning of goals, actual delivery and future plans.

12. **[P2, finding 7] Independent rebuild never severs unavailable AI field provenance.** `DocumentWorkspace.tsx:315` does not send sever_generation_fields or inspect lineage. Native `service.revise_document()` intentionally retains old lineage unless explicitly severed after a changed independently authored field. A reviewer native HTTP fixture probe generated and selected body/subject, revoked its reviewed model release, then submitted an independent human rewrite with the same shape as the UI. Native revision returned 201 but content:null/source_status:unavailable because old provenance was retained. Repeating with explicit sever_generation_fields for the independently rewritten body/subject produced readable content. Therefore UI rebuild can report success while the document remains unusable. Expose a deliberate independent replacement action for the relevant unavailable derivative fields and submit the native severing contract only for changed human-authored replacements. Preserve provenance for copied/unchanged generated text.
